## 二、LangGraph 迁移：动机与设计决策

### 2.1 动机

Phase 1 的 `agent_core` 是自研轻量技能插件框架（orchestrator 扫描 skills/、tool_registry、safety、logger、memory），只承担最简单的编排（UI 直接调 `fetch_emails` → `classify_emails`），没有任何 agent 循环。

Phase 2+ 将引入**多步骤流程**：摘要 → 草拟 → **人工确认** → 发送，以及需求文档 2.1 规划的 **Router + Tool-use Loop** 交互模式——多步、有状态、需 human-in-the-loop，正是 LangGraph 的适用场景。

### 2.2 已确认的设计决策

| 决策 | 结论 |
| :--- | :--- |
| 迁移范围 | 整个 agent_core 重写为 LangGraph（工具注册 + 安全网关融入图调用链） |
| 技能形态 | 技能 = **子图**，保留插件扫描机制（新技能加子图，不改核心装配代码） |
| 边界结构 | 一个 Agent **超级图**（Router 入口节点 + 各技能子图） |
| 状态定义 | `AgentState` TypedDict（route/request/emails/classified/messages/errors），节点增量填充 |
| 持久化 | LangGraph `MemorySaver`（内存 checkpointer）**替代 memory.py** |
| 执行方式 | Subagent-Driven Development：每任务独立实现者 + 评审者，按任务提交（用户批准，git 历史由用户最后整理） |

设计文档：`docs/superpowers/specs/2026-08-07-langgraph-migration-design.md`
实施计划：`docs/superpowers/plans/2026-08-07-langgraph-migration.md`（7 任务 TDD，含完整代码）

### 2.3 新架构总览

```
用户层（Streamlit UI）          —— UI 经 agent.invoke({"route": ...}) 驱动，不再直接调工具
   ▼
Agent 超级图（agent_core/graph.py）—— 入口 router 节点按 route 分发
   ├── email 技能子图（skills/email/graph.py）：fetch → classify → END
   │
   工具调用一律经 safe_call（安全网关包裹）
基础设施：tool_registry · safety · logger（保留）；memory.py（废弃删除）
```

## 五、遇到的问题与解决

| 问题 | 原因 | 解决 |
| :--- | :--- | :--- |
| 真实模式分类 400 报错 | `LLM_MODEL=deepseek-v4-flash` 缺 provider 前缀 | `.env` 改为 `deepseek/deepseek-v4-flash` |
| `.env` 未加载 | 用户先填了 `.env.example` 而非复制为 `.env`，且 `LLM_MODE` 被注释 | 生成 `.env`、恢复 `.env.example` 为干净模板（密钥只在 gitignored `.env`） |
| 邮件 id 为 bytes（`b'2860'`） | IMAP search 返回 bytes | mail_fetcher 解码为 str |
| 子代理在 GM-Assistant 内 `git init` 建了嵌套仓库 | 实现者未遵循外层仓库约定 | 移除嵌套 `.git`，统一用 `git -C "C:/intern"` 按文件提交 |
| Task 5 实现者误读「用户自己提交」而不提交 | 与「子代理按任务提交」的约定冲突 | 控制器指示补交，并记录于 ledger |
| 子图测试 invoke 报「未注册工具」 | 工具注册发生在 `orchestrator.scan()`，测试未触发 | test_email_graph 加 module 级 autouse fixture 调 `orchestrator.scan()` |
| AppTest 相对路径 `FileNotFoundError` | `from_file` 按测试文件目录解析相对路径 | 测试改用 `_PROJECT_ROOT / <path>` 绝对路径 |
| 最终评审：指向未装配技能的 route 会使整图崩溃 | `path_map` 只含已构建子图，`route_path` 可能返回其外名字 | `route_path` 绑定 `valid_targets`，未装配目标退化为 END（修复轮） |
| 裸 `pytest`（不带 `python -m`）跑测试失败 | 项目根不在 sys.path | 新增 `pytest.ini`（`pythonpath = .`） |
| 真实模式一次 LLM 调用卡 ~8.5 分钟 | 本地代理网络延迟（环境问题） | 等待恢复，非代码缺陷；仅记录 |
